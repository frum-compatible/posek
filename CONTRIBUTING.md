# Contributing

A ha’arah should include the shailah, relevant metzius and minhag, actual
answer, mareh mekomos, and a concise explanation of the difficulty.
Explain whether the correction changes the psak l’maaseh.

Correctness is not measured by strictness. Preserve distinctions among law,
custom, personal stringency, before-the-fact practice, and after-the-fact
validity. Do not use a public development answer key as an authority.

When changing a rule, add a meaningful counterexample to the benchmark. Keep
questions separate from expected behavior. Have disputed labels reviewed by
qualified readers, and publish their role with consent. A reviewer is not an
endorser unless they explicitly say so.

Never fabricate sources, quotes, credentials, affiliations, bans, reviews, or
test results. Discuss arguments and institutions without attacking people for
their religious identity. No harassment campaigns or unsolicited targeting.

Do not include private she'eilot, names, intimate details, credentials, or work
material in issues, commits, test fixtures, and screenshots. Use synthetic
scenarios. Keep retrieved translations outside the repository unless their
license and required attribution have been reviewed.

Run code and structure checks on GitHub Actions. The initial project was built
under a CI-only local-machine constraint; do not represent unrun checks as
passing. Behavioral model evaluations need their own saved outputs and clear
conditions; they are distinct from software unit tests.

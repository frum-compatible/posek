# Evaluate Posek

The public development cases live in the repository's `benchmarks/` directory; they are not installed as authority or loaded during ordinary questions. Use that suite for regression work, not to substantiate a claim that the software is an accredited posek.

Evaluate practical correctness under stated assumptions, source fidelity, attribution, treatment of minhag, material disagreement, and handling of uncertainty. Score whether the answer gives a supported conclusion rather than indiscriminately refusing or indiscriminately permitting.

For divrei Torah, use the separate editorial cases under `benchmarks/divrei-torah/`. Review source fidelity and attribution as factual requirements, then assess the actual interpretive point, the validity of the argument, the specificity of the payoff, and the audience and length fit. A fluent piece with an invented source fails source fidelity. Do not reuse the psak rubric or call subjective prose ratings an accuracy percentage. Compare ordinary generation, revision, and pressure to distort sources; preserve the candidate's actual output before review.

Read `benchmarks/README.md` in the source repository for the test protocol. If the skill was installed without the benchmark package, request the repository or test cases. Do not fabricate a suite or a score.

Use isolated candidate sessions with the skill and the question only. Keep answer keys and previous scores out of the candidate context. Pair cases that differ by one controlling fact. Run the same questions with and without the skill under equivalent model/tool settings before claiming improvement. Public development cases are not an unseen test set.

Record exact model identifier when known, host, time, skill hash, tools, retrieval failures, candidate outputs, and evaluator qualifications. An assistant assessing another assistant is still an AI assessment. Require independent qualified human review before presenting a score as expert-validated halakhic accuracy. Report sample sizes, failures, exclusions, coverage and abstention; a source-fetch success rate is not a ruling-accuracy rate.
